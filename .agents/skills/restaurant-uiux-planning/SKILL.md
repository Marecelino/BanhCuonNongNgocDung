# Restaurant UI/UX Planning Skill

## Goal
Create a research-grounded design plan for a small restaurant website before implementation.

## Workflow
1. Inspect the current project and collect verified business facts from the conversation and project docs.
2. Research current restaurant website patterns from real restaurant examples, current industry guidance, and visual references. Record the source, date/context, observed pattern, and how it applies. Separate inspiration from evidence; do not copy a full design.
3. Identify user intents: check menu/prices, decide whether the food fits, call/order, open Zalo, find the shop, check opening hours.
4. Build 2–3 plausible art directions and recommend one with rationale tied to the shop and its audience.
5. Produce user journeys, one-page information architecture, desktop wireframe, mobile-specific wireframe, tablet behavior, design tokens, component inventory, content/asset requirements, accessibility/performance standards, and QA plan.
6. Identify all unknown business facts as blockers/TODOs.
7. Run a design critique against the brief and explain trade-offs.
8. Stop at a plan-only gate. Do not write UI code until the user approves the plan.

## Design principles
- Food photography should be authentic, consistent, and the visual focus.
- Menu and prices must be real text, not a poster image or PDF-only menu.
- Make phone, Zalo, location, and opening hours easy to reach.
- The smallest screen has its own hierarchy and navigation behavior.
- Keep the layout lightweight; reject animation/3D unless a measurable user benefit exists.
- Avoid generic AI-looking layouts, random gradients, excessive pill cards, fake reviews, and invented claims.
